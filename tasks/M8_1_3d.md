## 0. Proje bağlamı (5 dakikada MATOKI)

MATOKI, tarayıcıda **GPU kullanmadan** çalışan bir yazılım render motorudur. Her şey sıfırdan:

- **Motor:** C11, freestanding, `clang --target=wasm32 -nostdlib`. libc yok, malloc yok (arena allocator), Emscripten yok.
- **JS:** yalnızca ince platform katmanı (`web/platform.js`): wasm yükleme, input, framebuffer'ı canvas'a kopyalama, JIT modülü instantiate etme, worker'lar.
- **Rasterizer:** `src/raster/` — 24.8 sabit nokta, top-left kuralı, 64×64 karo binning, 2×2 quad'lar, wasm SIMD, derinlik tamponu (early-z), blend modları. 3D için perspektif-doğru interpolasyon yolu (`RasterVert.inv_w`) **yazılmış ama hiç gerçek 3D sahnede kullanılmamış**.
- **Matoki:** projenin kendi shader dili (`docs/MATOKI.md`). ISPC tarzı SPMD: shader tek piksel için yazılır, derleyici 2×2 quad'ın 4 pikseli için **wasm SIMD**'e derler. Derleyici (lexer → parser → sema → IR → optimizasyon → codegen) **motorun içinde, çalışma anında** çalışır; çıktı wasm modülü `WebAssembly.Instance` olarak yüklenip paylaşılan fonksiyon tablosuna konur, C onu fonksiyon işaretçisiyle çağırır (`ShadeFn`). Uniform özelleştirme (sabit uniform'ları koda gömme) ve blend füzyonu var. Matoki JIT çıktısı clang'ın derlediği eşdeğer C shader'dan sprite'ta ~3×, plasma'da ~4.7× hızlı ölçüldü.
- **Doğruluk kâhini:** `ir_eval` (`src/matoki/ir_eval.c`) IR'ı skaler C ile çalıştırır. Codegen ile **bit-bit** aynı olmak zorunda; 500 rastgele programlık diferansiyel test (`tests/test_matoki_back.c`, node ile) bunu her `make test`'te doğrular.
- **Diğer kendi araçlarımız:** `mbin` (wasm binary üretici), `masm`/`mdis` (kendi WAT assembler/disassembler'ımız, `wat2wasm` ile byte-byte aynı), PNG kodlayıcı/çözücü (sıfırdan DEFLATE/inflate) `src/img/png.c`, prosedürel doku üreteçleri `src/img/procgen.c`, noise `src/img/noise.c`, bitmap font + immediate-mode UI `src/ui/`, iş sistemi + worker thread'ler `src/thread/`.
- **Build:** `make` → `build/engine.wasm` (+ `web/engine.wasm`), `make test` → native (host) testler + wasm-validate, `make serve` → `http://localhost:8080` (COOP/COEP başlıklı; SharedArrayBuffer açık).
  - `src/**/*.c` otomatik toplanır. `*_wasm.c` yalnızca wasm'a girer. `tests/*.c` host test koşucusuna girer (`tests/test.h`: `TEST(isim) { CHECK(...); CHECK_NEAR(a,b,eps); }`). `tools/host/tool_X.c` → `build/host/X` native araç. `shaders/*.mtk` otomatik olarak wasm'a gömülür (`src/core/embed.h`).
  - Host testlerinde libc serbest (`tests/`, `tools/host/`); `src/` altında yasak.
  - Test ortamında `node` (v22), `python3`, `wabt` (`wasm-validate`, `wasm2wat`, `wat2wasm`) mevcut.

## 2. Önceden onaylanmış mimari değişiklikler (bunları yapabilirsin)

### 2.1 Doku mip zinciri (ABI)
`shade_abi.h`'deki `Texture` struct'ının boyutu (32 byte) ve mevcut ofsetleri **değişmeyecek**. `_pad` alanı yeniden adlandırılır:
```c
u32 levels;   /* mip seviye sayısı, >= 1. (eski _pad; 0 görülürse 1 kabul et) */
#define TEX_OFF_LEVELS 28
#define TEX_FLAG_MIPMAP 4u
```
**Yerleşim:** tüm seviyeler `px`'ten başlayarak bitişik. Seviye k'nın genişliği `wk = max(1, w >> k)`, yüksekliği `hk = max(1, h >> k)`. Seviye k'nın başlangıcı: `px + Σ_{i<k} wi*hi`. Kare olmayan dokular desteklenir. `levels <= 1 + log2(max(w,h))`.

### 2.2 Türevler (IR)
`ir.h`'ye iki opcode **eklenir** (enum'un sonuna, `IR_OP_COUNT`'tan önce; mevcut numaralar kaymasın — kayıyorsa testlerdeki sabit beklentileri güncelle):
- `IR_DERIV_X (a: f32)` → **kaba (coarse)** türev: tüm 4 lane'e `v[lane1] - v[lane0]`
- `IR_DERIV_Y (a: f32)` → tüm 4 lane'e `v[lane2] - v[lane0]`
- Lane sırası (`shade_abi.h`): lane0=(x,y) lane1=(x+1,y) lane2=(x,y+1) lane3=(x+1,y+1).
- Operand uniform ise sonuç `const 0.0f` (constfold bunu yapar). Sonuç her zaman varying.
- **Maskeden bağımsız:** türev, quad'ın 4 lane'inin hesaplanmış değerleri üzerinden alınır (kapsanmayan "yardımcı lane"ler dahil). Bunun doğru çalışması için rasterizer'ın kapsanmayan lane'ler için de varying'leri düzlem denklemiyle **dışdeğerlemesi** gerekir — **önce doğrula** (`raster.c`'yi oku, test yaz). Yapmıyorsa M6_2 ile çakışmayacak şekilde ele al: ya M6_2 bitince düzelt ya da `docs/DECISIONS.md`'ye yaz ve bildir.
- Varying IF içinde: bölge çalışıyorsa tüm lane'ler hesaplanmış durumdadır (SPMD), türev yine 4 lane'den alınır. Deterministik; `ir_eval` aynısını yapmalı.
- Codegen: `i8x16.shuffle` ile lane yayma + `f32x4.sub` (2 shuffle + 1 sub). ir_eval: lane aritmetiği.

### 2.3 Mipmap'li örnekleme semantiği (C referansı ve Matoki BİREBİR uyar — bit-bit)
`sample(tex, uv)` doku `@mipmap` ile bildirilmişse (`TEX_FLAG_MIPMAP`):
1. `dudx = dFdx(u) * w`, `dvdx = dFdx(v) * h`, `dudy = dFdy(u) * w`, `dvdy = dFdy(v) * h` (w,h = seviye 0 boyutu, f32).
2. `px2 = dudx*dudx + dvdx*dvdx`, `py2 = dudy*dudy + dvdy*dvdy`, `rho2 = max(px2, py2)` (f32, `max` = wasm `f32.max` semantiği; NaN → kural: NaN ise seviye 0).
3. **Seviye (tamsayı, karekök/log yok, bit-exact):** `e = ((bits(rho2) >> 23) & 0xFF) - 127` (yani `floor(log2(rho2))`), `level = e >> 1` (aritmetik kaydırma = `floor(log2(rho))`). `rho2 < 1` (e < 0) → `level = 0`. Sonra `level = min(level + lod_bias, levels - 1)`, `lod_bias` = 0 (v0'da sabit; ileride uniform). Denormal/0 → seviye 0.
4. Seçilen seviyede mevcut en-yakın/bilinear + wrap/clamp semantiği (`shade_abi.h` yorumundaki formüller) seviyenin `wk, hk` değerleriyle (`w_mask` yerine `wk-1`; wrap için `wk` 2'nin kuvveti olduğundan geçerli).
5. Trilinear (iki seviye arası lerp) **v0'da yok**; Faz 5 esnek hedef: `@trilinear` — kesirli kısım rho2'nin mantisinden lineer yaklaşımla; semantiğini önce `DECISIONS.md`'ye yaz.

### 2.4 Matoki dil eklemeleri
- Yerleşikler: `dFdx(x)`, `dFdy(x)`, `fwidth(x) = abs(dFdx(x)) + abs(dFdy(x))` — `f32/vec2/vec3/vec4` aşırı yüklemeleri.
- `uniform t: texture2d @mipmap;` (mevcut `@bilinear @clamp` ile birleştirilebilir).
- `sample_level(tex, uv, level: i32)` — açık seviye (gölge/özel kullanım için).
- `texel_fetch(tex, ivec2) -> u32`-benzeri ham erişim ve `bitcast_f32(i32) -> f32` (gölge haritasında derinliği float bitleri olarak saklamak için; IR'da `IR_TEXEL_LOAD` + `IR_BITCAST_I2F` zaten var). İsimlendirmeyi `MATOKI.md`'ye işle.
- `mat4`/`mat3` uniform'larla `mat * vec4` çarpımı (sema/lower'da mevcut mu kontrol et; yoksa ekle).

### Faz 1 — 3D boru hattı çekirdeği (`src/gfx3d/pipeline.*`, `camera.*`)

**İş:**
- `Mesh` (SoA: `f32* px, py, pz; f32* nx, ny, nz; f32* u, v; u32* indices; u32 vertex_count, index_count`; opsiyonel tangent ve vertex rengi), `Material` (Matoki shader varyantı + uniform bloğu + doku slotları), `DrawItem` (mesh, materyal, model matrisi).
- Vertex aşaması (C, SIMD'li olabilir — `*_wasm.c` + skaler yedek): model→dünya→klip (`Mat4`), varying hesaplama (dünya konumu, normal = normal matrisi ile, UV).
- **Kırpma (homojen uzayda):** yakın düzlem (`z >= 0`, WebGPU/D3D tarzı 0..1 derinlik; `src/core/math.c`'deki `mat4_perspective`'in konvansiyonunu kontrol et ve ona uy) ile **gerçek kırpma** (Sutherland–Hodgman, varyingler doğrusal interpolasyon klip uzayında). Diğer 5 düzlem için **guard band**: 24.8 sabit noktanın taşmayacağı ekran sınırı hesapla (raster'ın kabul ettiği koordinat aralığını `raster.c`'den oku), yalnızca guard band dışına taşan üçgenleri kırp. `w <= epsilon` güvenliği.
- Perspektif bölme, viewport dönüşümü, `RasterVert { x, y, z, inv_w, var[] }` doldurma — varyingler **`var * inv_w`** olarak mı verilmeli yoksa raster mı çarpıyor? `raster.c`'nin perspektif-doğru yolunu oku ve sözleşmeyi Notlar'a yaz.
- Arka yüz ayıklama (`raster_set_cull` veya pipeline'da işaretli alan ile), sıfır alanlı/alt-piksel üçgen eleme.
- Nesne başına frustum culling (bounding sphere + AABB), sahne başına istatistik: gönderilen/elenen/kırpılan üçgen.
- `Camera`: perspektif + FPS uçuş kontrolü (WASD + fare, pointer lock), orbit modu, FOV/near/far ayarı.
- Derinlik: `raster_set_depth(r, TRUE, TRUE, DEPTH_LESS)` (veya reverse-Z kullanıyorsan GREATER — seçimini gerekçelendir: f32 derinlikle reverse-Z hassasiyet avantajı ölçülebilir).

**Testler (`tests/test_gfx3d_pipeline.c`):**
- Kırpma: yakın düzlemi kesen 10.000 rastgele üçgen → çıkan çokgenler düzlemin doğru tarafında, köşe varyingleri analitik değerlerle 1e-5 içinde, alan korunumu (kırpılmış parçaların toplam alanı = düzlemin içindeki kısmın alanı).
- **Çatlak yok:** ortak kenarlı iki üçgen yakın düzlemi keserken → raster sonrası ortak kenarda boşluk/çift boyama yok (raster'ın host derlemesiyle framebuffer'a çizip piksel say).
- Perspektif-doğru interpolasyon: eğik düzlemde dama tahtası; piksel merkezlerinde UV'nin analitik değerine 1e-4 tolerans.
- Frustum culling doğruluğu (bilinen konumlar).

**Kabul:** `web/3d.html`'de dönen, dokulu, derinlik testli bir küp + düzlem + 1000 küplük ızgara; kamera ile içinden geçince (yakın düzlem kırpması) bozulma yok.

### Faz 4 — Işıklandırma ve materyaller (Matoki shader'ları)

**İş (`shaders/` altına):**
- `lit.mtk`: Lambert + Blinn-Phong, 1 yönlü ışık + 8'e kadar nokta ışık (uniform dizi yoksa sabit sayıda ayrı uniform veya `for` döngüsü — Matoki'nin `for i in 0..N` sabit sınırlı döngüsü var), ambient/hemisfer ışığı, uzaklık sisi, gama (lineer → sRGB çıkışta; yaklaşık `sqrt` veya polinom — maliyetini ölç).
- `pbr.mtk`: glTF metallic-roughness (GGX NDF, Smith-Schlick G, Schlick Fresnel), baseColor/metallicRoughness/normal/emissive dokuları. Normal map için tangent uzayı (varying tangent + bitangent işareti).
- `unlit.mtk`, `alpha_mask.mtk` (discard), alpha BLEND materyaller için ayrı geçiş (arkadan öne sıralama, nesne düzeyinde).
- Gökyüzü: tam ekran prosedürel gökyüzü shader'ı (`sky.mtk` — gradyan + güneş diski + basit Rayleigh benzeri ton; kameranın ters view-projection'ı uniform), derinlik testi en uzakta.
- Materyal sistemi: shader varyant önbelleği (`src/matoki/variant.h` — D'nin yazdığı; incele ve kullan): sabit uniform'lar (ör. metallic=0, doku yok) → **uniform özelleştirmeyle** daha kısa varyantlar. Kaç varyant üretildiğini ve kısalma oranını ölç.
- C referans karşılığı: en az `lit.mtk` için C referans shader (`ref_shaders.c`) — Matoki ile karşılaştırma (tol 2/255, transandantal yaklaşımlar yüzünden bit-bit beklenmez; nedenini Notlar'a yaz).

**Testler:** `ir_eval` ile `lit.mtk`'nin bilinen girdilerde elle hesaplanan değere eşitliği (1e-4); PBR enerji korunumu kaba testi (beyaz fırın testi: roughness taraması, çıktı ≤ 1 + eps).

**Kabul:** 3D demoda ışıklandırılmış sahne; ışıkları UI kaydırıcılarıyla (`src/ui/ui.h`) değiştirebilme. Notlar: shader başına IR komut sayısı, wasm boyutu, Mquad/s; varyant önbelleği istatistikleri.

### Matoki çekirdeği v0 (2026-10-27)
§0'da var sayılan Matoki derleyicisi sıfırdan yazıldı (`src/matoki/`, `src/jit/`, belge: `docs/MATOKI.md`).
- **lexer** (`lexer.c`), **parser** (`parser.c`, özyinelemeli iniş, konumlu hatalar), **sema** (`sema.c`: tipler,
  isimler, 37 yerleşik, uniform/varying yerleşimi, özyineleme tespiti), **lower** (`lower.c`: skalerleştirme,

  **codegen** (`codegen.c`: doğrudan wasm ikili, SIMD128), **JIT** (`jit_wasm.c` + JS'te `plat_jit_instantiate`).

  §2.4'ten `dFdx/dFdy/fwidth`, `texel_fetch`, `bitcast_f32/i32` var; `@mipmap`, `sample_level`, `mat * vec` yok.
